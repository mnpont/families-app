# Practice Hub + Conjugation Drill — Spec

What was built for the Practice hub and the Conjugation Drill, how it works, and how to extend it. The visual design comes from the Claude Design handoff "Practice Hub + Conjugation Drill" (screens 0–9 plus the component sheet). The handoff isn't committed to the repo. Behavior, data and logic follow the task brief wherever the handoff differed. The main differences: conjugations come from a rule-based library (not an LLM, not a static table), and the drill pool is "has conjugations", not `partOfSpeech === 'verb'`.

## 1. What was built

- **Practice hub** (screens 1a/1b). This is the default Practice-tab screen: a list built from the registry in `src/constants/exercises.ts`.
  - Multiple Choice → the previous Practice screen, moved unchanged into `MultipleChoiceView.tsx`. It shows an "N due" pill.
  - Conjugation Drill → enabled for French and shows an "N verbs" pill. In other languages it shows the "French only for now" tag.
  - Fill the Gap and Build the Sentence → "Coming soon".
- **Conjugation Drill** (screens 2–6): the setup sheet, question, correct/almost/wrong feedback, summary, empty state and loading state.
- **Conjugate pill + modal** in Families (7a/7b).
- **Data:** `words.conjugations` (migration 016). It's generated by the `generate-conjugations` Edge Function after every add or edit, and backfilled by `scripts/backfillConjugations.ts`.

Navigation is sub-state inside `PracticeView` (no router): `hub → setup sheet → drill → summary → hub`, and `hub → multipleChoice`. `App` keys `PracticeView` on `language:resetKey`. So switching language, or tapping the Practice nav button while already on Practice, remounts it back to the hub.

Not built: Fill the Gap and Build the Sentence (screens 8–9) and `WordChip`. **Their design already exists in the handoff (screens 8a/8b, 9a/9b and the component sheet)**, so a future session can start from there. Fill the Gap reuses `PracticeProgress`, `AnswerInput`, `FeedbackCard`, `ConjugationTable` and `SessionSummary` as they are.

Learning principles this follows (`docs/learning-science.md`):

- typed production, never picking from options;
- retrieval practice;
- interleaving (verbs, persons and tenses mixed, never blocked by verb);
- immediate explicit corrective feedback.

It's free practice: no spaced repetition, no `review_log` writes, no schedule table. Multiple Choice and the SRS are untouched.

## 2. Spike results (Step 1)

**Route taken: the library, in an Edge Function.** The Node-script route and the LLM fallback weren't needed.

- **Libraries:** `french-verbs@5.4.0` (Apache-2.0) and `french-verbs-lefff@3.4.0`.
  - The Lefff data is under LGPL-LR (Lesser General Public License for Linguistic Resources). That's fine for a personal/open project: keep the licence notice with the data, which the npm package does.
  - The package also pulls in `french-contractions` (Apache-2.0) and `french-verbs-transitive` (CC BY-SA 3.0 word list).
- **Runs in a Supabase Edge Function.** I tested it in the real `supabase/edge-runtime` container (v1.69.6) with the hosted limits: 256 MB memory, 2 s CPU.
  - The dictionary is a 6.3 MB JSON file with 7,826 verbs.
  - Import and parse take about 70 ms. The heap sits around 35 MB once loaded.
  - Generating one verb's full table takes about 1 ms and produces 3.5–4.6 KB of JSON.
  - The functions import it with `npm:` specifiers and a JSON import attribute.
- **Correctness.** Checked against an independent dataset (Verbiste, via `conjugation-fr`) for 155 common verbs' present tense and participles, plus by hand against standard reference conjugations. The library's forms are right. What it gets wrong or leaves to the caller is fixed in `supabase/functions/_shared/conjugationCore.ts`:
  - **Auxiliary.** Its être list misses monter/descendre/sortir/rentrer/retourner/passer, and it throws for verbs it doesn't know are transitive (even `être`).
    - Our list is used instead. For the dual verbs, the avoir form is also accepted ("a monté").
  - **Agreement.** It gives one form per call. We generate the variants: je/tu m./f., nous m./f., vous ×4.
    - Pronominal verbs whose reflexive is an indirect object (se parler, se téléphoner, …) stay invariable: "elles se sont parlé".
  - **Reflexive elision bug.** It elides the reflexive before the auxiliary for mute-h verbs ("je m'suis habillé"). We add the reflexive ourselves.
  - **Lefff quirks:**
    - `je puis` → `peux` (puis still accepted);
    - payer/essayer → "paie" and "paye" both accepted;
    - asseoir → "assieds" forms first, "assois" still accepted;
    - résoudre's participle "résous" → "résolu".
  - **Impersonal verbs.** falloir/pleuvoir keep only the persons they have.
  - **Non-verb keys.** A few Lefff keys aren't verbs ("voilà", "voici"); they're rejected by requiring an -er/-ir/-re ending.
- **Spot checks.** All passing, and kept as tests in `tests/conjugationCore.test.ts`:
  - être, avoir, aller, faire, pouvoir, vouloir, devoir, savoir, venir, prendre, dire, voir, mettre, tenir;
  - manger (mangeons), commencer (commençons), appeler (appelle), acheter (achète);
  - se lever (me lève / me suis levé(e));
  - être agreement: elle est allée, ils sont allés, elles sont allées.
- **German, for later.** `german-verbs@5.4.0` (Apache-2.0) with `german-verbs-dict@3.4.0`: 5.5 MB of data, CC BY-SA 4.0 (attribution + share-alike on the data).
  - Same load profile in Deno (~70 ms, ~26 MB).
  - Its API returns separable verbs split in two (`["stehe", "auf"]`), so the German generator will need to join them.

## 3. The `conjugations` shape

Documented in `migrations/016_add_words_conjugations.sql`. The types are `StoredConjugations` (generator) and `Conjugations` (`src/types/conjugations.ts`, app).

```json
{
  "version": 1,
  "source": "lefff",
  "infinitive": "lever",
  "pronominal": true,
  "hAspire": false,
  "auxiliary": "etre",
  "tenses": {
    "present": { "je": "me lève", "tu": "te lèves", "il": "se lève", "elle": "se lève", "nous": "nous levons", "vous": "vous levez", "ils": "se lèvent", "elles": "se lèvent" },
    "passe_compose": {
      "je": ["me suis levé", "me suis levée"],
      "elle": "s'est levée",
      "vous": ["vous êtes levé", "vous êtes levée", "vous êtes levés", "vous êtes levées"]
    }
  }
}
```

- **Tenses stored.** Every personal tense the library supports:
  - present, imparfait, passe_simple, futur;
  - passe_compose, plus_que_parfait, passe_anterieur, futur_anterieur;
  - conditionnel_present, conditionnel_passe, conditionnel_passe_2;
  - subjonctif_present, subjonctif_imparfait, subjonctif_passe, subjonctif_plus_que_parfait;
  - imperatif_present (tu/nous/vous; pronominal as "lève-toi").
  - Imperatif passé and the non-finite forms take no subject, so they're not stored.
- **Persons.** je, tu, il, elle, nous, vous, ils, elles. A person holds a string or an array of accepted variants, and the first is canonical. A person the verb doesn't have is absent.
- **Forms** are everything typed after the subject pronoun. Pronominal forms include the reflexive ("me lève").
- **je / j'** is derived, not stored. It elides when the form starts with a vowel, or with an h unless `hAspire` is set (haïr → "je hais"). The same rule lives in `conjugationCore.ts` (`startsWithElidingSound`) and in `src/constants/conjugation.ts`.
- **`source: "llm"`** is reserved for a fallback that doesn't exist.
- **`version`** lets a future shape change be told apart. After a bump, regenerate with `batch-generate-conjugations { "force": true }`.

## 4. Verb detection (Step 3)

`planConjugationUpdate` in `conjugationCore.ts` is shared by the Edge Function, the batch function and the backfill:

1. Not in `CONJUGATION_LANGUAGES` (`['fr']`) → no-op.
2. `part_of_speech` set to anything but `'verb'` → no-op.
3. Normalize the text:
   - trim, lowercase, unify apostrophes, collapse spaces;
   - a leading le/la/l'/les/un/une/des → skip (it's a noun);
   - strip a leading "se "/"s'" and remember it's pronominal;
   - must be a single word ending in -er/-ir/-ïr/-re.
4. Found in the dictionary → store `conjugations`. If `part_of_speech` was null, also set it to `'verb'` and clear `gender`: a Wikidata noun sense of the same spelling may have set one, and saving the word as a verb in Edit Word would clear it the same way.
5. Not found → leave the word alone. If it's tagged `'verb'`, log it. If it has stale conjugations (its text was edited away from a verb), clear them.

**Changing a word's type away from 'verb': the data is filtered out, not cleared.** `isConjugatable` (`src/utils/conjugationForms.ts`) is the single gate for both the drill pool and the Conjugate pill. It requires conjugations, a word type that is null or `'verb'`, and a language with a drill config. Changing the type back restores the word instantly with no regeneration.

**Accepted limitation:** a noun saved without its article ("dîner") is tagged as a verb. Change its type in Edit Word and it drops out.

`generate-conjugations` is fired and forgotten from `createWord` and `updateWord`, next to the sentence/distractor calls. Adding a word never waits on it.

## 5. Grading rules

`src/utils/gradeConjugation.ts`, pure:

- **Normalize both sides:**
  - NFC, lowercase, trim, collapse spaces;
  - unify ' and ’ (and remove spaces around them);
  - strip trailing punctuation.
- **Strip one leading subject pronoun** the learner typed ("nous allons", "j'ai mangé"). The unstripped input is kept as a second candidate, since "nous levons" and "nous nous levons" both make sense for se lever.
- **correct:** matches any accepted variant.
- **almost:** matches after removing diacritics (NFD + `\p{Diacritic}`, plus œ→oe, æ→ae). The feedback marks every expected letter the learner didn't type exactly: a missing accent, or a wrong one.
- **wrong:** anything else. The feedback shows the variant closest to the input (Levenshtein; ties keep the canonical one) and highlights the difference:
  - Words are aligned first.
  - A misspelled word gets letter-level highlighting ("allé" → "allé**s**").
  - A replaced or missing word is highlighted whole.
- **Score** is "correct on the first try". Almost and wrong both count as not correct, and each appears in the summary with its own dot colour.
- **Note line** ("aller uses **être** in the passé composé", "se lever is pronominal, so it uses **être** …"): shown in the wrong card and the Conjugate modal, for compound tenses whose auxiliary is être (which covers every pronominal verb).

## 6. Queue

`src/utils/buildConjugationQueue.ts`, pure, with an injectable `random`:

- **Session size.** 20 questions (`DRILL_SESSION_SIZE`), or fewer when the selected tenses don't have that many verb × tense × person combinations. The setup sheet's "N verbs · M questions" uses the same count.
- **Order.** Built greedily: the least-used verb/tense/person wins each slot, with a little noise.
  - The same verb never comes twice in a row, unless it's the only verb.
  - Repeating the previous person or tense costs extra.
  - The same combination never repeats.
- **A wrong answer** is re-inserted 3–5 positions later (`RETRY_OFFSET_MIN/MAX`), at most twice per question (`MAX_RETRIES_PER_ITEM`). An offset that would put the same verb twice in a row is avoided when possible. An "almost" isn't re-inserted.
- **Progress** ("7/20") and the summary total count original questions only, so they never exceed the session size. A question counts once Next is tapped.

## 7. Keyboard (iOS)

iOS Safari, including as an installed PWA, only opens the keyboard for a `focus()` that happens inside the user's tap. So:

- Every transition into a question (Start, Next, Practice again) commits with `flushSync`.
- The drill focuses the same, never-remounted input inside that tap.
- Check blurs the input, which closes the keyboard, and the button becomes Next in place. Enter also moves on.
- The Check button's `mousedown` is prevented, so tapping it doesn't blur the input before grading.
- `visualViewport` resize only scrolls the input back into view if it ended up covered.

Verified in Chromium with iPhone emulation. Test on a real device after deploying.

## 8. How to…

**Add or enable an exercise.** Edit `EXERCISES` in `src/constants/exercises.ts`: flip its `status` to `() => 'enabled'` (or a per-language function). Then handle its id in `PracticeView`'s `onSelect` and render its component for a new `PracticeMode`. The hub picks it up automatically, including a count pill if you add one in `PracticeHub.countFor`.

**Enable a tense.** Set `offered: true` on its entry in `FRENCH_TENSES` (`src/constants/conjugation.ts`), and `defaultOn: true` if its chip should start on. It then shows as a chip in the setup sheet and a section in the Conjugate modal.

French offers six tenses today, matching handoff screen 2b: Présent, Passé composé, Imparfait, Futur simple, Conditionnel and Plus-que-parfait. Présent and Passé composé start on; the other four start off. Subjonctif is defined but not offered. It's already stored for every verb, so nothing needs regenerating. One caveat: the subjunctive prompt would read better with "que" before the pronoun, a small addition to `ConjugationPrompt` when that tense is enabled.

**Add German** (no UI changes):

1. Add `'de'` to `CONJUGATION_LANGUAGES` in both `src/constants/conjugation.ts` and `supabase/functions/_shared/conjugationCore.ts`.
2. Add a `de` entry to `CONJUGATION_CONFIG`:
   - persons: ich, du, er, sie, es, wir, ihr, sie (pl.), Sie;
   - `tableRows`, tenses, `subjectPronouns`;
   - `pronounLabel` (no elision);
   - `displayInfinitive` ("sich waschen");
   - `note` (haben/sein).
3. Add a German generator next to `buildFrenchConjugations`, using `german-verbs` + `german-verbs-dict`:
   - join separable verbs ("stehe auf");
   - choose haben/sein per verb;
   - add the reflexive for "sich" verbs.
4. Dispatch to it in `planConjugationUpdate` by language, and run the backfill.

The hub's "French only for now" tag then disappears on its own, because the registry's status reads `CONJUGATION_LANGUAGES`.

## 9. Deploy steps

In order. The app's new query selects `words.conjugations`, so **apply the migration before merging** (Vercel deploys `main` automatically, and the query fails on a missing column):

1. Apply `migrations/016_add_words_conjugations.sql` in the Supabase SQL editor.
2. Deploy the functions:

   ```
   supabase functions deploy generate-conjugations
   supabase functions deploy batch-generate-conjugations
   ```

   No secret needed.
3. `npm run backfill:conjugations-dry-run` (reads `.env.local`). It lists the words it would tag as verbs, the verb-typed words that already get conjugations, and the verb-typed words it couldn't conjugate. Review the first list for nouns saved without an article.
4. `npm run backfill:conjugations-live`.
5. Merge. Later gaps (a failed per-add call) are swept by invoking `batch-generate-conjugations` with an empty body.
